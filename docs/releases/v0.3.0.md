# AirPlay Windows v0.3.0 — GPU rendering and recording

This release keeps mirrored video on the GPU from decoding through display
and hardware recording, eliminating the previous per-frame CPU readback and
upload in the display path.

## Highlights

- D3D11VA H.264/HEVC decoding with GPU color conversion, shared textures and
  GPU fence synchronization on the same graphics adapter.
- Reused decoder surface views and render targets, plus a one-frame display
  queue to limit accumulated presentation delay.
- GPU-resident H.264/HEVC MP4 recording with hardware encoders that accept
  D3D11 surfaces. Scaling and letterboxing stay on the GPU, including when
  the sending device changes orientation.
- The recording codec status identifies the actual path as **[GPU resident]**,
  **[GPU encoder, CPU pixels]** or **[CPU]**. Explicit GPU recording does not
  silently download GPU-decoded images; Auto can use a compatible fallback.
- Automatic or manual display rotation (0, 90, 180 and 270 degrees), saved
  between launches. Recording preserves the received orientation.
- Generic device labels and square resolution limits for phones, tablets and
  other AirPlay devices. The options show the actual received resolution.

## Using the GPU path

Enable **OPTIONS > Mirror Decoder > GPU decode**, then reconnect the sending
device. Select **Auto** or **GPU** in the recording panel. On a compatible
encoder, the recording status shows **[GPU resident]**. Audio encoding and
writing compressed MP4 packets still run on the CPU.

Extract the Windows x64 ZIP and run `airplay-windows.exe` from the extracted
folder, with the supplied DLLs alongside it. Existing saved settings are retained.

## Validation

Hardware integration tests passed on an NVIDIA GeForce RTX 3080 Laptop GPU:
H.264/HEVC CPU and GPU decoding, live codec/resolution changes, all four display
rotations, full/limited color range, and concurrent display and MP4 recording.
Generated recordings were decoded to verify pixels, letterboxing, AAC audio and
monotonic video timestamps. GPU-resident recording reported zero CPU readbacks;
CPU recording and software-decoded input were also checked.

Local rendering measurements are not end-to-end AirPlay latency measurements.
