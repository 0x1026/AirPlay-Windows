# AirPlay Windows v0.4.0 — Playback, stability & interface improvements

## Playback and stability

- Audio-only playback uses sender NTP and RTP timestamps to schedule sound.
  IPv4 timing support and clock acquisition have been corrected.
- Pause/resume handling preserves buffered audio across the sender's temporary
  audio-stream teardown, improving short and long pauses and reducing gaps.
- Remote playback commands remain available while the audio control session
  is active, including during longer pauses.
- Cover-art decoding uses correctly padded FFmpeg buffers, fixing a heap
  corruption issue.
- Audio-only interface refreshes do less work while newly received video frames
  still wake the renderer immediately.

## Interface and settings

- A new English interface with Home, Music and Screen Mirroring views, vector
  icons and a settings drawer.
- Fullscreen, recording and Hide interface keyboard shortcuts work with the
  interface visible, without intercepting text entry.
- Manual resizing works with both the full interface and Hide interface.
  The displayed image keeps its aspect ratio.
- Diagnostics visibility, window size, position and maximized state, plus
  recording folder, codec, encoder and bitrate are restored between launches.
- Preferences save automatically after changes settle. Settings files are
  replaced atomically, and existing settings remain compatible.
- **Reset all settings** restores app defaults without deleting recordings.
- GPU acceleration is enabled by default for new settings and after reset.
  Existing saved CPU choices are preserved; software decoding remains available.
- Screen Mirroring has a quick rotation menu sharing the same saved setting as
  the settings drawer, plus a discreet decoding-mode note.
- Connection help is presented as a readable card with network, VPN and
  firewall troubleshooting steps.

## Windows Firewall

- Background checks look for inbound access for the exact executable and the
  active Windows network profiles.
- A warning appears consistently in Home, Music and Screen Mirroring when
  access needs attention.
- **Allow on local network** requests administrator permission and creates an
  inbound application rule limited to the local subnet. Conflicting block
  rules for that executable are resolved on the active profiles.
- Administrator-enforced restrictions, failed checks and cancelled permission
  requests are reported separately. Rules are rechecked automatically.

## Current limits

Playback progress is read-only. Direct iTunes video clips can still behave
differently from audio tracks around pause/resume. The direct audio-only iOS
disconnect/route-indicator issue remains under investigation. These changes do
not add native Windows media-panel integration.

The automated checks cover firewall policy evaluation, settings persistence,
socket shutdown, audio timing and cover-art decoding. Interface layouts and
window transitions have also been checked locally. The elevated firewall-rule
update requires the user's Windows administrator approval.

Release validation passed all five regression tests and all 26 AirPlay protocol
checks. Hardware tests on an NVIDIA GeForce RTX 3080 Laptop GPU also passed
H.264/HEVC decoding, resolution and codec changes, display rotation, and MP4
pixel/audio/timestamp checks. GPU-resident recording paths reported zero CPU
readbacks; CPU and software-decoded fallback paths were checked separately.
